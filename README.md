# Intro-Path Discovery

Система импортирует контакты пользователя из LinkedIn, обогащает профили и строит граф связей.
По целевой компании или человеку она находит самые короткие и сильные пути для знакомства по сигналам:
**общий работодатель, вуз, совет директоров, взаимодействия в LinkedIn, совместные статьи**.

Пользователь загружает контакты, указывает цель и получает ранжированные пути знакомства: **кто и через
кого может представить**. У каждого пути есть **оценка силы** и **перечень сигналов** со ссылками на источники.

| Что внутри | Где смотреть |
|---|---|
| Веб-интерфейс (Streamlit): загрузка, цель, пути, граф, веса | [Интерфейс](#интерфейс) |
| Командная строка: импорт, обогащение, поиск путей, генерация демо | [Командная строка](#командная-строка) |
| LLM-агент с тремя инструментами и подтверждением человеком | [LLM-агент](#llm-агент) |
| Демо-данные (вымышленные), согласованные с SEC EDGAR и OpenAlex | [Демо-данные](#демо-данные) |
| Спецификация и чек-лист проверки | [docs/SPEC.md](docs/SPEC.md), [docs/CHECKLIST.md](docs/CHECKLIST.md) |

Пакет `intro_paths` **не обращается к LinkedIn**: вход — файлы, которые пользователь сам скачал
(*Settings → Data privacy → Get a copy of your data*). Внешние источники (SEC EDGAR, OpenAlex, Crossref)
запрашивают только **цель**, а не контакты. Экспериментальный скрипт `scripts/fetch_linkedin.py`
(неофициальный API, нарушает ToS LinkedIn) в пакет не входит.

## Быстрый старт

Нужен Python 3.11+.

```bash
python -m venv .venv
.venv/Scripts/python -m pip install -e ".[dev,app]"      # Linux/macOS: .venv/bin/python
cp .env.example .env                                      # заполните нужные переменные (см. ниже)

.venv/Scripts/python -m streamlit run src/intro_paths/app.py   # интерфейс
.venv/Scripts/python -m pytest                                 # тесты
```

Интерфейс работает сразу на демо-данных, ключи не нужны. Переменные `.env`:

| Переменная | Для чего | Обязательна |
|---|---|---|
| `SEC_USER_AGENT` | контакт в User-Agent для SEC EDGAR, формат `Имя Фамилия you@example.com` | для живого EDGAR |
| `OPENALEX_API_KEY` | бесплатный ключ OpenAlex: без него доступна только первая страница работ автора | нет |
| `OPENALEX_MAILTO`, `CROSSREF_MAILTO` | «вежливый» пул API | нет |
| `API_KEY`, `API_LINK` | ключ и адрес OpenAI-совместимого API для агента | для агента |
| `ANTHROPIC_API_KEY` | только если агент запускается на Claude | нет |
| `LINKEDIN_*` | только для экспериментального `scripts/fetch_linkedin.py` | нет |

Файл `.env` в репозиторий не попадает (`.gitignore`).

## Интерфейс

```bash
streamlit run src/intro_paths/app.py
```

В боковой панели выбирается набор данных: **Демо: Apple (SEC EDGAR)**, **Демо: Geoffrey Hinton (OpenAlex)**
или **Мои данные (ZIP экспорта LinkedIn)**. Вкладки:

| Вкладка | Что показывает |
|---|---|
| Обзор | конвейер «импорт → обогащение → граф → пути → ранжирование», счётчики, цели проекта и их ограничения |
| Данные | контакты, инсайдеры SEC, работы OpenAlex (со ссылками на источники) |
| Граф | интерактивный граф (pyvis): слои, подсветка топ-путей, поиск узла, инспектор, статистика |
| Пути | рейтинг с полосой силы, разбор формулы с подстановкой, цепочки «через знакомого знакомого» |
| Как считается | слайдеры весов и пересчёт рейтинга («что если») |
| Источники и приватность | что уходит наружу, живое обновление цели из EDGAR/OpenAlex |

### Сценарий: загрузил контакты → указал цель → получил пути

1. Выберите «Мои данные». Готовые демо-файлы скачиваются кнопками в панели (или лежат в `data/demo/`):
   `linkedin_export_demo.zip` и `enrichment.csv` (необязательно). Либо поставьте галочку
   «Использовать встроенный демо-ZIP».
2. Загрузите ZIP экспорта LinkedIn.
3. Укажите цель: тип (компания или человек), название, при желании тикер. Для демо: **Apple Inc** или
   **Geoffrey Hinton**.
4. Выберите источники: «Офлайн-снимки SEC/OpenAlex» (без интернета) или живые SEC EDGAR / OpenAlex / Crossref.
5. Нажмите «Найти пути»: список «кто может представить» с силой и сигналами, разбор формулы, блок
   «Через знакомого знакомого» и граф.

Ожидаемый результат на демо: для Apple Inc — John Ternus 0.96, Kevan Parekh 0.88, Deirdre O'Brien 0.76;
для Geoffrey Hinton — Max Marlowe 0.84 и Ilya Sutskever 0.84 (общий работодатель + совместные работы).

## Командная строка

| Команда | Что делает |
|---|---|
| `intro-paths import` | разбирает экспорт LinkedIn (и `enrichment.csv`) в `network.json` |
| `intro-paths enrich-target` | загружает данные цели: SEC EDGAR для компании, OpenAlex/Crossref для человека |
| `intro-paths paths` | ищет и ранжирует пути к цели (`--json` для машинного вывода) |
| `intro-paths synth` | генерирует демо-набор в `data/demo/` |
| `intro-paths agent` | запускает LLM-агента |

```bash
# 1. Разобрать экспорт
intro-paths import --export-dir data/sample/export --enrichment data/sample/enrichment.csv --out network.json

# 2. Обогатить цель
intro-paths enrich-target --target-company "Apple Inc" --ticker AAPL --out-target target.json     # EDGAR, только США
intro-paths enrich-target --target-person "Jane Doe" --out-target target.json                     # OpenAlex, затем Crossref

# 3. Найти пути
intro-paths paths --network network.json --target target.json --limit 5

# Глубокий режим: имена топ-N совпавших контактов уходят во внешние API, чтобы подтвердить общие работы
intro-paths enrich-target --target-person "Jane Doe" --deep --top 20 \
    --network network.json --out-network network.deep.json --out-target target.json
```

### Что берётся из экспорта

| Файл экспорта | Что берём |
|---|---|
| Profile.csv | имя владельца |
| Connections.csv | контакты, URL профиля, текущая компания |
| Positions.csv, Education.csv | места работы и учёба владельца с датами |
| Messages.csv | число сообщений и дата последнего (текст не читается) |
| Invitations.csv | факт и дата приглашения |
| enrichment.csv | история работы, вузы, советы контактов — вручную |

Экспорт не содержит историю контактов и связи между ними, поэтому такие данные добавляются через
`enrichment.csv`:

```
person_id,kind,name,start,end,role
ivan-petrov-example,education,Московский университет (пример),2010,2014,Магистр
pavel-novikov-example,board,Example Corp,2016-01,2018-12,Член совета директоров
```

`person_id` — часть URL профиля после `/in/` (или `me` для владельца); `kind` — `position`, `education`
или `board`; даты — `2019`, `2019-03`, `2019-03-15`, пустой `end` означает «по настоящее время».

## Как считается сила пути

- **Сигналы по организациям:** общий работодатель 0.6, общий вуз 0.5, общий совет директоров 0.9.
- **Сигналы по людям:** директор целевой компании (SEC) 0.9, офицер 0.7; соавторство с целью —
  0.5 + 0.1 за каждую дополнительную общую работу, максимум 0.85.
- **Понижающие коэффициенты:** даты неизвестны ×0.5; совпало только имя, без общей организации или работы ×0.5;
  свидетельство старше 5–6 лет ×0.7.
- **Сила пути** = `1 − Π(1 − wᵢ)` (noisy-OR): независимые сигналы усиливают друг друга, но не складываются линейно.
- **Тепло связи** (переписка и приглашения из экспорта) — множитель `0.5 + 0.5 · тепло` к итоговой силе.
  Если в экспорте есть переписка, а у контакта её нет, тепло равно нулю. Без `Messages.csv` и
  `Invitations.csv` множитель равен 1.
- **Цепочки через знакомого знакомого** (3 хопа): сила(мост→цель) × сила(контакт–мост) × скидка 0.5 × тепло.
  Мост — директор SEC или соавтор цели, которого нет в вашей сети. Это оценка по общей организации,
  а не подтверждённое знакомство.

Все веса собраны в `ScoringConfig` (`scoring.py`): `find_intro_paths(..., cfg=ScoringConfig(school=0.8))`.
В интерфейсе то же делают слайдеры. Веса стартовые и не калиброваны на размеченных кейсах.

## LLM-агент

Агент с ручным циклом и тремя инструментами:

| Инструмент | Назначение | Риск |
|---|---|---|
| `enrich_target` | данные о цели из SEC EDGAR или OpenAlex | читает внешние сервисы |
| `find_intro_paths` | ранжированные пути среди контактов пользователя | только чтение |
| `request_introduction` | ставит в очередь черновик просьбы о знакомстве | **действие**, только после подтверждения |

Каждый инструмент описан по восьми полям (имя, описание, аргументы, что не от модели, результат, ошибки, тип,
отказ) в [docs/SPEC.md](docs/SPEC.md); тест `test_spec_describes_every_tool_*` следит, чтобы описание не
расходилось с кодом.

Защиты: схема аргументов (`additionalProperties: false`), ошибки возвращаются модели с `is_error`, владелец и
контакты берутся из сессии, а не от модели, таймаут вызова, ограничение размера результата, лимит шагов.
Действие `request_introduction` выполняется только после «y» человека и лишь сохраняет черновик в
`data/outbox/` — ничего не отправляется.

Провайдер и модель задаются в [config/agent.toml](config/agent.toml): по умолчанию `qwen/qwen3.8-27b` через
OpenAI-совместимый API (`API_KEY`, `API_LINK` в `.env`). Альтернативы: `config/agent.anthropic.toml` (Claude),
`config/agent.demo.toml` (офлайн, без ключа).

```bash
# Живое демо: настоящая модель; первый вызов SEC падает по таймауту, агент выходит из ошибки
intro-paths agent --config config/agent.demo-live.toml --request "Кто из моих контактов может представить меня Apple Inc? Подготовь запрос лучшему кандидату."

# Обычный запуск
intro-paths agent --request "Кто из моих контактов может представить меня Apple Inc?"

# Офлайн, без ключа и сети: «модель» воспроизводит записанный сценарий
intro-paths agent --config config/agent.demo.toml --request "Найди пути к Apple Inc"
```

В модель уходят результаты инструментов (имена контактов, сигналы): на реальных данных это передача
персональных данных провайдеру. Подробности — в [docs/SPEC.md](docs/SPEC.md).

## Демо-данные

```bash
intro-paths synth --out-dir data/demo      # детерминированно, seed=7
intro-paths paths --network data/demo/network.json --target data/demo/targets/apple.json
```

В `data/demo/`: экспорт LinkedIn (`export/` и готовый `linkedin_export_demo.zip`), `enrichment.csv`,
`network.json`, цели `targets/apple.json` и `targets/hinton.json`, снимки публичных данных `snapshots/`,
сценарии `scenarios.json`, `DISCLAIMER.md`.

68 вымышленных контактов согласованы с публичными данными SEC EDGAR (Apple) и OpenAlex (Geoffrey Hinton).
Имена директоров и соавторов взяты только для сопоставления; должности, связи и переписка вымышлены, ссылки
на профили имеют вид `/in/demo-…`. Сценарии: офицер подтверждён местом работы, директор «только имя» (×0.5),
однофамилец, соавтор подтверждён вузом или общими работами, соавтор без подтверждения, тёплые и холодные
контакты. Не публикуйте набор как реальную сеть знакомств.

## Ограничения

- SEC EDGAR покрывает только компании, подающие отчётность в США; периоды работы директоров приблизительные
  (по датам форм 3/4/5). Совет директоров других компаний добавляется вручную через `enrichment.csv`.
- Google Scholar не подключён: у него нет API, `/scholar` закрыт в robots.txt и защищён капчей. Интерфейс
  `PublicationSource` (`sources/base.py`) позволяет добавить платный SerpApi.
- Образование цели-человека из OpenAlex не приходит — вводится вручную в аффилиациях цели.
- Сопоставление людей по имени ненадёжно (однофамильцы, Tim/Timothy, транслитерация): без подтверждения
  общей организацией вес снижается вдвое.
- Нет словаря алиасов организаций («Сбер» ↔ «Сбербанк»), только грубая нормализация.
- Связи контакт–контакт и 3-й хоп выведены по общей организации, а не подтверждены.
- Внешние запросы кэшируются в `data/.cache/` на 24 часа. Персональные данные контактов хранятся в открытом
  JSON: для реального использования нужны шифрование и политика хранения (152-ФЗ, GDPR).
