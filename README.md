# intro-paths

Импорт экспорта LinkedIn, граф связей и поиск путей знакомства с ранжированием по сигналам.

Пакет `intro_paths` **не обращается к LinkedIn**. Вход — файлы, которые пользователь
сам скачал через *Settings → Get a copy of your data*. Внешние источники (SEC EDGAR,
OpenAlex, Crossref) запрашивают только **цель**, а не контакты. Отдельный
экспериментальный скрипт `scripts/fetch_linkedin.py` (неофициальный API, нарушает ToS
LinkedIn) в пакет не входит.

## Установка

```bash
python -m pip install -e ".[dev,app]"   # app = Streamlit-интерфейс
cp .env.example .env                    # SEC_USER_AGENT обязателен для EDGAR
```

## Интерфейс

```bash
streamlit run src/intro_paths/app.py
```

Боковая панель: набор данных (синтетика Apple / Geoffrey Hinton или ваш ZIP экспорта), число путей,
для своих данных — цель и источники. Вкладки:

| Вкладка | Что показывает |
|---|---|
| Обзор | конвейер «импорт → обогащение → граф → пути → ранжирование», счётчики, цели проекта и их ограничения |
| Данные | контакты, инсайдеры SEC, работы OpenAlex (со ссылками на источники) |
| Граф | интерактивный граф (pyvis): слои, подсветка топ-путей, поиск узла, инспектор, статистика |
| Пути | рейтинг с полосой силы, разбор формулы с подстановкой, 3-хоповые цепочки |
| Как считается | слайдеры весов и пересчёт рейтинга («что если») |
| Источники и приватность | что уходит наружу, живое обновление цели из EDGAR/OpenAlex |

## LLM-агент

Агент с ручным циклом и тремя инструментами: `enrich_target`, `find_intro_paths`, `request_introduction`.
Модель — любая за OpenAI-совместимым API; по умолчанию `qwen/qwen3.8-27b` через routerai.ru.
Спецификация и контракты — [docs/SPEC.md](docs/SPEC.md), чек-лист — [docs/CHECKLIST.md](docs/CHECKLIST.md).

В `.env` задайте `API_KEY` (ключ) и `API_LINK` (адрес API, например `https://routerai.ru/api/v1`); провайдер,
модель и лимиты — в `config/agent.toml`.

```bash
# Живое демо: настоящая модель, первый вызов SEC падает по таймауту, агент выходит из ошибки
intro-paths agent --config config/agent.demo-live.toml --request "Кто из моих контактов может представить меня Apple Inc? Подготовь запрос лучшему кандидату."

# Обычный запуск
intro-paths agent --request "Кто из моих контактов может представить меня Apple Inc?"

# Офлайн (без ключа и сети): «модель» воспроизводит записанный сценарий
intro-paths agent --config config/agent.demo.toml --request "Найди пути к Apple Inc"

# Claude вместо Qwen: ANTHROPIC_API_KEY в окружении и другой конфиг
intro-paths agent --config config/agent.anthropic.toml --request "..."
```

Защиты: схема аргументов (`additionalProperties: false`), ошибки возвращаются модели с `is_error`,
владелец и контакты берутся из сессии, таймаут вызова, `result_max_chars`, `max_steps`, а действие
`request_introduction` выполняется только после «y» человека и лишь ставит черновик в `data/outbox/`.
Провайдер и модель меняются в `config/agent.toml` без правки кода (`openai_compatible`, `anthropic`, `scripted`).
В модель уходят результаты инструментов (имена контактов, сигналы): на реальных данных это передача
персональных данных провайдеру.

## Демо-данные (синтетика)

```bash
intro-paths synth --out-dir data/demo      # детерминированно: seed=7
intro-paths paths --network data/demo/network.json --target data/demo/targets/apple.json
intro-paths paths --network data/demo/network.json --target data/demo/targets/hinton.json
```

68 вымышленных контактов, согласованных с публичными снимками SEC EDGAR (Apple) и OpenAlex
(Geoffrey Hinton) из `data/demo/snapshots/`. Имена директоров/офицеров Apple и соавторов Хинтона
взяты только для сопоставления; должности, связи и переписка вымышлены (`data/demo/DISCLAIMER.md`),
URL профилей — `/in/demo-…`. Сценарии (`data/demo/scenarios.json`): офицер подтверждён местом
работы, директор «только имя» (×0.5), однофамилец, соавтор подтверждён вузом/общими работами и
соавтор без подтверждения, тёплые и холодные контакты. Не публикуйте набор как реальную сеть.

## Граф

`intro_paths.graph`: узлы — владелец, контакты, организации, вузы, работы, цель, инсайдеры SEC,
«мосты»; рёбра — контакт, работа, учёба, совет, соавторство, инсайдер, коллеги (выведено,
пунктиром). Организации показываются, если их делят ≥2 человека или они связаны с целью.
`find_chain_paths` ищет цепочки владелец → контакт → мост → цель, где мост (директор SEC или
соавтор цели) не входит в сеть; сила = сила(мост→цель) × сила(контакт–мост) × скидка 0.5 × тепло.
Это оценка по общей организации, а не подтверждённое знакомство.

## Что если

Все веса собраны в `ScoringConfig` (`scoring.py`); `find_intro_paths(..., cfg=ScoringConfig(school=0.8))`
пересчитывает рейтинг. В интерфейсе то же делают слайдеры на вкладке «Как считается».

## Обогащение цели

```bash
# Цель-компания: директора и офицеры из SEC EDGAR (только компании США)
intro-paths enrich-target --target-company "Apple Inc" --ticker AAPL --out-target target.json
# Цель-человек: работы и соавторы из OpenAlex, затем Crossref
intro-paths enrich-target --target-person "Jane Doe" --out-target target.json
# Глубокий режим: имена топ-N совпавших контактов уходят во внешние API, чтобы подтвердить общие работы
intro-paths enrich-target --target-person "Jane Doe" --deep --top 20 \
    --network network.json --out-network network.deep.json --out-target target.json

intro-paths paths --network network.json --target target.json
```

## Использование

```bash
# 1. Разобрать экспорт (и, опционально, ручное обогащение)
intro-paths import --export-dir data/sample/export --enrichment data/sample/enrichment.csv --out network.json

# 2. Найти пути к цели
intro-paths paths --network network.json --target data/sample/target_person.json --limit 5
intro-paths paths --network network.json --target data/sample/target_company.json --json
```

## Что извлекается

| Файл экспорта     | Что берём                                  |
|-------------------|--------------------------------------------|
| Profile.csv       | имя владельца                              |
| Connections.csv   | контакты, URL профиля, текущая компания    |
| Positions.csv     | места работы владельца с датами            |
| Education.csv     | учёба владельца с датами                   |
| enrichment.csv    | история работы, вузы, советы контактов (вручную) |
| Messages.csv      | число сообщений и дата последнего (текст не читается) |
| Invitations.csv   | факт и дата приглашения                    |

Экспорт не содержит историю контактов и связи между ними — поэтому такие данные
добавляются через `enrichment.csv`.

### Формат enrichment.csv

```
person_id,kind,name,start,end,role
ivan-petrov-example,education,Московский университет (пример),2010,2014,Магистр
pavel-novikov-example,board,Example Corp,2016-01,2018-12,Член совета директоров
```

- `person_id` — slug из URL профиля контакта (часть после `/in/`), или `me` для владельца;
- `kind` — `position`, `education` или `board`;
- `start` / `end` — `2019`, `2019-03`, `2019-03-15`; пустой `end` = по настоящее время.

## Цель

JSON-файл с аффилиациями. Для компании — одна запись `position`:

```json
{"name": "Example Corp", "affiliations": [{"kind": "position", "name": "Example Corp"}]}
```

## Скоринг

- Сигналы по организациям: общий работодатель 0.6, общий вуз 0.5, общий совет директоров 0.9.
- Сигналы по людям: директор целевой компании (SEC) 0.9, офицер 0.7; соавторство с целью
  0.5 + 0.1 за каждую дополнительную общую работу, максимум 0.85.
- Понижающие коэффициенты: даты неизвестны ×0.5; совпало только имя (нет общей организации
  или общей работы) ×0.5; свидетельство старше 5–6 лет ×0.7.
- Сила пути = `1 - Π(1 - w_i)` (noisy-OR).
- «Тепло» связи с контактом (сообщения, приглашения из экспорта) — множитель `0.5 + 0.5·тепло`
  к итоговой силе. Без `Messages.csv`/`Invitations.csv` множитель равен 1.
- Веса стартовые: их нужно калибровать на размеченных кейсах.

## Ограничения (что ещё не сделано)

- Нет словаря алиасов организаций («Сбер» ↔ «Сбербанк») — только грубая нормализация.
- Нет LLM-извлечения сигналов из свободного текста.
- Путь всегда 2 хопа; последнее звено «контакт → цель» выведено по общим атрибутам, а не подтверждено.
- SEC EDGAR покрывает только компании, подающие отчётность в США; периоды работы директоров —
  по датам подачи форм 3/4/5, то есть приблизительные. Совет директоров других компаний
  добавляется вручную через `enrichment.csv`.
- Google Scholar не подключён: у него нет API, `/scholar` закрыт в robots.txt и защищён капчей.
  Интерфейс `PublicationSource` (`sources/base.py`) позволяет добавить платный SerpApi.
- Сопоставление людей по имени ненадёжно (однофамильцы, никнеймы вроде Tim/Timothy,
  транслитерация): без подтверждения общей организацией вес снижается вдвое.
- Внешние запросы кэшируются в `data/.cache/` (24 часа).
- Персональные данные контактов хранятся в открытом JSON — для реального использования нужны шифрование и политика хранения (152-ФЗ).
