# Спецификация: сервис поиска пути знакомства и его агент

## Пользователь и задачи

**Пользователь** — человек, который хочет выйти на компанию или конкретного человека и ищет, кто из его
контактов LinkedIn может его представить. Данные контактов он выгрузил сам (*Get a copy of your data*).

**Задачи**
1. «Кто из моих контактов может представить меня компании X / человеку Y?» — найти и ранжировать пути.
2. «Почему именно он?» — объяснить силу пути и перечислить сигналы: общий работодатель, вуз, совет директоров,
   директор или офицер из SEC, совместные статьи, взаимодействия в LinkedIn.
3. «Через кого?» — показать контакт и, если связь идёт через знакомого знакомого, мост.
4. «Подготовь запрос лучшему кандидату» — поставить в очередь черновик просьбы о знакомстве
   (только после подтверждения человеком).

Чего сервис **не** делает: не ходит в LinkedIn, не отправляет сообщения сам, не выдумывает контакты и связи.

## Сервис: две части

| Часть | Что делает | Запуск |
|---|---|---|
| **Веб-интерфейс** | пользователь загружает контакты (ZIP экспорта LinkedIn), указывает цель и получает ранжированные пути: кто и через кого может представить, у каждого пути оценка силы и перечень сигналов | `streamlit run src/intro_paths/app.py` |
| **Агент** | то же на естественном языке: модель сама вызывает инструменты, объясняет результат и готовит запрос на знакомство | `intro-paths agent --request "…"` |

Оба слоя используют один движок (`paths.py`, `scoring.py`, `graph.py`), поэтому результаты совпадают.

## Инструменты: восемь полей

У агента три инструмента. Поля: **имя, описание, аргументы, что не от модели, результат, ошибки, тип, отказ**.
Код: `src/intro_paths/agent/tools.py`.

### 1. `enrich_target`

| Поле | Значение |
|---|---|
| **Имя** | `enrich_target` |
| **Описание** | Подгружает данные о цели из внешних источников: для компании — директоров и руководителей из SEC EDGAR (только компании США), для человека — научные работы и соавторов из OpenAlex. Вызывать один раз в начале, до `find_intro_paths`. Не трогает контакты пользователя, ничего не отправляет. |
| **Аргументы** | `target` — строка 1–120 символов, обязательно; `kind` — `company` или `person`, обязательно; `ticker` — строка по шаблону `^[A-Za-z.]{1,6}$` (например `AAPL`), необязательно. Схема с `additionalProperties: false`: любые другие поля отклоняются. |
| **Что не от модели** | Источник данных и режим (`enrichment = snapshot` или `live` в конфиге); папка снимков; `SEC_USER_AGENT` и ключи из `.env`; таймаут вызова `tool_timeout_s`. Модель не выбирает, куда ходить и под каким именем. |
| **Результат** | JSON: `target`, `kind`, `insiders_found`, `works_found`, подсказка `next`. Цель сохраняется в сессии для `find_intro_paths`. |
| **Ошибки** | Нет данных о цели («продолжайте без обогащения»); таймаут сервиса; превышен `tool_timeout_s`; не задан `SEC_USER_AGENT`; неверные аргументы; внутренняя ошибка. Все возвращаются модели с `is_error`. |
| **Тип** | Чтение внешних сервисов. Побочных эффектов нет, подтверждение не нужно. |
| **Отказ** | Сервис недоступен или данных нет — вызов не падает: модель получает ошибку, по системному промпту повторяет один раз, затем идёт дальше без обогащения и сообщает об этом пользователю. |

### 2. `find_intro_paths`

| Поле | Значение |
|---|---|
| **Имя** | `find_intro_paths` |
| **Описание** | Ищет среди контактов пользователя тех, кто может представить его цели, и возвращает ранжированный список: `connector_id`, имя, сила пути 0–1 и сигналы (работодатель, вуз, совет директоров, директор или офицер SEC, совместные статьи, переписка). `include_chains=true` добавляет пути «через знакомого знакомого» — это оценка, не подтверждение. Только читает данные. |
| **Аргументы** | `target` — строка 1–120, обязательно; `kind` — `company` или `person`, обязательно; `limit` — целое 1–10, по умолчанию 5; `include_chains` — логическое, по умолчанию `false`. `additionalProperties: false`. |
| **Что не от модели** | Сеть контактов и владелец (`Session.network`, загружены пользователем); «сегодня» (`Session.today`); обогащённая цель из сессии; веса и коэффициенты (`ScoringConfig`). В схеме нет ни `owner_id`, ни пути к файлу, ни идентификатора клиента. |
| **Результат** | JSON: `target`, `enriched`, `found`, `paths` — список `{rank, connector_id, name, strength, signals[{code, detail, weight, source}]}`; при `include_chains` — `through_acquaintance[{via_id, via_name, bridge, bridge_role, strength}]`; если цель не обогащена — подсказка `hint`. Размер ограничен `result_max_chars`, при обрезке добавляется пометка. |
| **Ошибки** | Неверные аргументы (например `limit=500`, не тот тип, лишнее поле); превышен `tool_timeout_s`; внутренняя ошибка. Пустой список — не ошибка (`found = 0`). |
| **Тип** | Только чтение. Подтверждение не нужно. |
| **Отказ** | Если связей нет, возвращается `found = 0` и подсказка, а не исключение; модель обязана сказать об этом, а не выдумывать контакты. |

### 3. `request_introduction`

| Поле | Значение |
|---|---|
| **Имя** | `request_introduction` |
| **Описание** | **Действие.** Ставит в очередь запрос на знакомство через выбранный контакт. Вызывать только когда пользователь явно просит подготовить запрос и только для `connector_id` из `find_intro_paths`. Сообщение не отправляется: сохраняется черновик для ручной отправки. |
| **Аргументы** | `connector_id` — строка 1–100, обязательно; `target` — строка 1–120, обязательно; `message` — строка 10–600 символов, обязательно. `additionalProperties: false`: поля вроде `confirmed` или `skip_confirmation` отклоняются схемой. |
| **Что не от модели** | **Владелец** (`session.owner_id` — записывается в файл кодом); **подтверждение** (спрашивает человека `session.confirm`, модель на него повлиять не может); существование контакта (проверка по сети сессии); папка очереди (`outbox_dir`); лимит запросов (`max_intro_requests`, по умолчанию 3); статус записи `queued_for_manual_send`. |
| **Результат** | JSON: `queued: true`, `file` — путь к черновику `data/outbox/intro_<владелец>_<номер>.json`, `note` — «сообщение не отправлено». |
| **Ошибки** | Контакта нет в сети (проверяется до вопроса человеку); лимит запросов исчерпан; человек отказал; неверные аргументы; превышен `tool_timeout_s`. |
| **Тип** | **Опасное действие** (запись от имени пользователя). Выполняется только после явного «y» человека. |
| **Отказ** | Ответ «N», пустой ввод или отсутствие интерактивного ввода — отказ: действие не выполняется, файл не создаётся, модель получает «Человек отклонил действие. Ничего не сделано. Не повторяйте без нового указания пользователя.» Повтор без нового указания запрещён системным промптом. |

## Опасные действия

- `request_introduction` — единственное действие с побочным эффектом. Подтверждение по умолчанию — **отказ**;
  без интерактивного ввода — тоже отказ. Вопрос человеку показывает, кому и что именно будет поставлено в очередь.
  Реальной отправки нет — только черновик в `data/outbox/` (в git не попадает).
- Остальные инструменты читают данные и ничего не меняют.
- Модель не может обойти подтверждение через аргументы: схема не допускает лишних полей, а вопрос задаёт код.
- Текст запроса: системный промпт запрещает утверждать неподтверждённое («мы вместе работали»); человек видит
  текст до подтверждения.

## Сценарии ошибок

| Ситуация | Что происходит |
|---|---|
| Сервис обогащения не ответил (таймаут SEC) | `is_error`; модель повторяет один раз, затем идёт без обогащения и сообщает об этом |
| Неверные аргументы (limit=500, лишнее поле, не тот тип, битый JSON) | вызов не исполняется; ошибка схемы возвращается модели, она исправляет вызов |
| Вызов завис | таймаут `tool_timeout_s`; ошибка модели; агент жив и процесс не зависает на выходе |
| Неизвестный инструмент или `connector_id` | ошибка с перечнем допустимого |
| Человек отказал | `is_error`, «ничего не сделано»; повтор без нового указания запрещён |
| Результат слишком большой | обрезается до `result_max_chars` с пометкой |
| Модель зациклилась | лимит `max_steps`: остановка с понятным итогом |
| Сбой API модели (сеть, лимиты, ключ) | `LLMError`, аккуратное завершение, без трассировки |
| Отказ модели (`refusal`) или обрезка `max_tokens` | обрабатываются отдельно, цикл останавливается |

## Цикл и лимит шагов

`run_agent` (`agent/loop.py`): запрос модели → вызовы инструментов → все результаты одним сообщением → следующий
запрос. Максимум `max_steps` обращений к модели (по умолчанию 8); при исчерпании — остановка с итогом
«достигнут лимит шагов». Каждый вызов инструмента идёт через `execute_tool`, который проверяет схему,
ограничивает время и размер результата и **никогда не бросает исключение** наружу.

## Конфиг

`config/agent.toml`: `provider`, `model`, `api_key_env`, `base_url_env`, `max_steps`, `tool_timeout_s`,
`result_max_chars`, `max_intro_requests`, пути к данным, режим обогащения. Ни ключа, ни адреса API в конфиге
нет — только **имена** переменных окружения (`API_KEY`, `API_LINK` в `.env`).

Провайдеры: `openai_compatible` (по умолчанию `qwen/qwen3.8-27b` через routerai.ru), `anthropic`
(`config/agent.anthropic.toml`), `scripted` (офлайн-демо и тесты). Смена модели или провайдера — правка
конфига без изменения кода.

## Приватность

В модель уходят результаты инструментов: имена контактов, названия компаний, сигналы. Для демо — вымышленные
данные; с реальными контактами это передача персональных данных стороннему провайдеру (152-ФЗ, GDPR):
используйте провайдера, которому доверяете, или локальную модель за тем же OpenAI-совместимым адресом.

## Демо

- Живое: `intro-paths agent --config config/agent.demo-live.toml --request "…Apple Inc…"` — настоящая модель;
  первый вызов `enrich_target` падает по таймауту (имитация сбоя SEC), агент повторяет, находит пути,
  предлагает запрос и ждёт «y/N».
- Офлайн, без ключа и сети: `config/agent.demo.toml` — тот же сценарий, «модель» воспроизводит запись.
- «Ошибка → исправление»: `config/agent.demo-errors.toml` — `limit=50` нарушает схему, агент просит 10; имя вместо
  `connector_id` отклоняется, агент берёт id из результата. Транскрипты с реальных прогонов — `docs/AGENT_DEMO.md`.
- Интерфейс: `streamlit run src/intro_paths/app.py` → «Мои данные» → демо-ZIP → цель **Apple Inc** → «Найти пути».
