# Спецификация: агент поиска пути знакомства

## Пользователь и задачи
**Пользователь** — человек, который хочет выйти на компанию или конкретного человека и ищет, кто из его
контактов LinkedIn может его представить. Данные контактов он выгрузил сам (*Get a copy of your data*).

**Задачи агента**
1. «Кто из моих контактов может представить меня компании X / человеку Y?» — найти и ранжировать пути.
2. «Почему именно он?» — объяснить силу пути и перечислить сигналы (работодатель, вуз, совет директоров,
   директор/офицер из SEC, совместные статьи, переписка).
3. «Подготовь запрос лучшему кандидату» — поставить в очередь черновик просьбы о знакомстве
   (только после подтверждения человеком).

Что агент **не** делает: не ходит в LinkedIn, не отправляет сообщения сам, не выдумывает контакты и связи.

## Инструменты и контракты
| Инструмент | Вход (JSON Schema, `additionalProperties: false`) | Выход | Ошибки (возвращаются модели с `is_error`) | Риск |
|---|---|---|---|---|
| `enrich_target` | `target` (1–120 симв.), `kind` ∈ {company, person}, `ticker` (`^[A-Za-z.]{1,6}$`, необяз.) | `target`, `insiders_found`, `works_found`, подсказка «дальше» | таймаут сервиса; нет данных о цели; не задан `SEC_USER_AGENT` | читает внешние сервисы (только цель, не контакты) |
| `find_intro_paths` | `target`, `kind`, `limit` (1–10), `include_chains` (bool) | ранжированные пути: `connector_id`, имя, сила 0–1, сигналы с весами и ссылками на источники; цепочки «через знакомого» | неверные аргументы | только чтение |
| `request_introduction` | `connector_id`, `target`, `message` (10–600 симв.) | `queued`, путь файла очереди; сообщение **не** отправляется | контакта нет в сети; лимит запросов за сессию; человек отказал | **опасное действие** |

Владелец, его контакты и папка исходящих берутся из **сессии** — в схемах нет `owner_id`, путей и данных
клиента, лишние поля отклоняются.

## Опасные действия
- `request_introduction` — действие от имени пользователя. Выполняется **только после явного «y»** человека
  (по умолчанию — отказ, без интерактивного ввода — тоже отказ); перед вопросом проверяется, что
  `connector_id` существует; за сессию не больше `max_intro_requests` (3); реальной отправки нет — только
  черновик в `data/outbox/` для ручной отправки.
- Остальные инструменты читают данные и ничего не меняют.

## Сценарии ошибок
| Ситуация | Что происходит |
|---|---|
| Сервис обогащения не ответил (таймаут SEC) | `is_error` с текстом; по системному промпту агент повторяет один раз, затем продолжает без обогащения и сообщает об этом |
| Модель прислала неверные аргументы (limit=500, лишнее поле, не тот тип) | вызов не исполняется; ошибка схемы возвращается модели, она исправляет вызов |
| Вызов завис | таймаут `tool_timeout_s`, ошибка модели, агент жив |
| Неизвестный инструмент / `connector_id` | ошибка с перечнем допустимого |
| Человек отказал | `is_error` «ничего не сделано»; повтор без нового указания запрещён промптом |
| Результат слишком большой | обрезается до `result_max_chars` с пометкой |
| Модель зациклилась | лимит `max_steps`; остановка с понятным итогом |
| Сбой API модели (сеть, лимиты, ключ) | `LLMError`, аккуратное завершение, без трассировки |
| Отказ модели (`refusal`) / обрезка `max_tokens` | обработаны отдельно, цикл останавливается |

## Конфиг
`config/agent.toml`: `provider`, `model`, `api_key_env`, `base_url_env`, `max_steps`, `tool_timeout_s`,
`result_max_chars`, `max_intro_requests`, пути к данным, режим обогащения. Ни ключа, ни адреса API в
конфиге нет — только **имена** переменных окружения (`API_KEY`, `API_LINK` в `.env`).
Провайдеры: `openai_compatible` (по умолчанию: `qwen/qwen3.8-27b` через routerai.ru), `anthropic`
(Claude, `config/agent.anthropic.toml`) и `scripted` (офлайн-демо и тесты). Смена модели или провайдера —
правка конфига без изменения кода.

## Приватность
В модель уходят результаты инструментов: имена контактов, названия компаний, сигналы. Для демо — вымышленные данные;
с реальными контактами это передача персональных данных стороннему провайдеру (152-ФЗ/GDPR) — используйте
провайдера, которому доверяете, или локальную модель за тем же OpenAI-совместимым адресом.

## Демо
- Живое: `intro-paths agent --config config/agent.demo-live.toml --request "…Apple Inc…"` — настоящая модель;
  первый вызов `enrich_target` падает по таймауту (имитация сбоя SEC), агент повторяет, находит пути,
  предлагает запрос и ждёт «y/N».
- Офлайн (без ключа и сети): `config/agent.demo.toml` — тот же сценарий, «модель» воспроизводит запись.
